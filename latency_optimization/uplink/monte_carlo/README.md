# Uplink Monte Carlo

This is the offline train-and-test method. In payload mode, each training seed
creates one channel episode and later blocks are generated by the payload
rollout. In streaming mode, each training seed is one independent one-block
sample. The rollout selects the visited `n_kl` states; there are no expert
labels and no MSE beam loss.

The objective-only training loss is negative finite-blocklength rate. Payload
bits are allocated after the network beam and achieved rate are known.

Every streaming block requests a fresh `B[k]` bits per user, and missed bits do
not alter the following block's target.

Run:

```powershell
python -m latency_optimization run --link uplink --method monte_carlo --cfg_name uplink_dispersion_heavy.yaml --num_train_channels 11 --test_seed 3
```

For streaming, use block-count options instead:

```powershell
python -m latency_optimization run --link uplink --method monte_carlo --cfg_name uplink_streaming.yaml --num_train_blocks 11 --num_test_blocks 11 --test_seed 3
```

Training artifacts are under `training/data`; held-out evaluation results are
under `testing/data`. Payload samples are stored in `training/channels`, while
streaming samples are stored in `training/blocks`. Each directory has a
`manifest.json`, and every saved sample records a separate SNR value for every
user. Testing uses the corresponding `testing/channels` or `testing/blocks`
directory.

Actual network-training curves are stored in `training/optimization_history`.
The first training sample's post-training schedule and blocklength diagnostics
are stored separately in `training/evaluation`; they are not training epochs.

Payload testing uses `monte_carlo_num_test_channels`; streaming testing uses
`monte_carlo_num_test_blocks`. Their seeds are disjoint from the training seeds
and their SNR values use midpoint stratification within each user's range.
Held-out results are saved under `testing/samples`, while
`testing/data/test_dataset_summary.txt` reports the mean and standard
deviation across the complete test set.

The streaming scenario's `experiment_scenario.number_of_blocks` is used by
multi-block convergence runs. Monte Carlo intentionally sets it to one for
each sample, so the configured training and test block counts are direct
sample counts and are not multiplied by the scenario horizon.
